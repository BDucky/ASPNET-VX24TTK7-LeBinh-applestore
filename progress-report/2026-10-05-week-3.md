## What landed this week

- PR #9 (current Apple VN catalog, storefront on rauvang.com's page flow)
  and PR #10 (catalog synced with rauvang.com: configurations, VND prices,
  same-model photos) merged into `dev` on 2026-10-05. Build clean, 53 of
  53 tests pass on `dev`.
- `OrderStatus` resolved. The source report gives a value domain of 0 to
  4 but names only four values. Decision: the fifth value is "confirmed",
  placed between pending and shipping: Pending 0, Confirmed 1, Shipping 2,
  Completed 3, Cancelled 4. No migration was needed (no order rows yet,
  no default or check constraint). Recorded in `docs/data-model.md`,
  `docs/requirements.md`, and `docs/roadmap.md`. This unblocks M5.
- Plan for the rest of the project set: M1 (account pages), M3 (cart,
  checkout, voucher), M4 (payment: COD, VNPay and MoMo simulated unless
  sandbox credentials are available), M5 (order management), M7 (admin
  CRUD and revenue report), then the `thesis/` documents. M6 (stock and
  promotions) and M8 (reviews) come last and may be cut if time runs out.

- **M1 account features finished on ASP.NET Core Identity** (PR #12 and
  PR #13), all six account use cases:
  - Register with an emailed 6-digit code, sign in, sign out (use cases
    1-3). Identity runs over the report's own `Users` table through a
    custom `UserStore`, so the 24-table schema stays; 4 Identity columns
    were added by migration. Password at least 8 characters; 5 wrong
    passwords lock the account for 5 minutes.
  - Forgot password by emailed code stored hashed in `UserTokens`, change
    password, profile, and delivery addresses (use cases 4-6).
  - Test-first throughout: 111 tests, each behavior a RED commit then a
    GREEN commit.
  - Live browser check, rerunnable: `setup/verify-account/verify.py`, 69
    checks (every account page at desktop and phone width, error paths,
    lockout, another user's address refused, server error page).
- **Real email** (branch `feat/smtp-email`): codes can now be sent through
  Gmail SMTP with MailKit. Settings are read with the options pattern and
  checked at startup; the App Password stays in user-secrets, outside the
  repository. If sending fails the visitor sees a message and can try
  again. Tested for real: a registration code reached a Gmail inbox
  (confirmed by the owner); macOS needed one TLS setting relaxed, now an
  option.
- Reference used: a previous student's submission for the same course
  (report template and sample project). The 5-chapter report structure
  and its ASP.NET chapter (MVC, EF Core, Identity) shape the work above.
- `docs/finish-plan.md` added: task order, status, definition of done.
