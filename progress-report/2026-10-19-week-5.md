## 3. How the work was tested

No application code changed this week (report/slides and the tooling that
builds them only), so the usual RED/GREEN test cycle did not apply. What was
still checked for real, every time something changed:

1. `dotnet build --no-incremental` and `dotnet test` (647 passing) kept
   green throughout, confirming the report work never touched application
   code by accident.
2. Every PDF rebuild was rendered page by page (`pdftoppm`) and swept for
   near-blank pages, the same technique that caught the Quartz-only blank-
   image bug; the final 67-page version has zero flagged pages.
3. Individual pages were opened as images after each layout change (not
   just the page count) to catch regressions a page counter alone would
   miss, which is how the "full-page screenshot shrunk to an unreadable
   sliver" mistake (see section 4) was caught before it reached a finished
   deliverable a second time.
